Context & goals\n### 1.1 Product in one paragraph\nSruNal KZ prepares academic documents for Satbayev University students (реферат, лабораторная\nработа, презентация, СРС/СРСП). A client creates an order, pays via **Kaspi QR**, an operator\nverifies the payment manually, the generation worker produces the file, and the client downloads\nit for **30 days**. Support: `@meownuarka`.\n### 1.2 Why Telegram instead of a website\n| Problem with the website | Telegram solution |\n|---|---|\n| Sign-in friction (one-time codes on the web) | Identity comes for free from `initData` (chat id), no login screen at all |\n| Users miss status changes (they must re-open the site) | The bot pushes every transition into the chat with buttons |\n| Forms feel heavy on mobile browsers | A focused Mini App wizard with native `MainButton`, `BackButton`, haptics |\n| Users lose order links | Every order is bound to the chat; `/status` and the Mini App list them |\n### 1.3 Goals\n1. **Order creation in under 3 minutes** on a mid-range Android phone.\n2. **Zero-login:** opening the Mini App from the bot is the authentication.\n3. **Every state change is announced** by the bot with a clear next action.\n4. **Telegram-native look:** the app must feel like a Telegram settings screen, and must follow the\n   user's light/dark/custom theme automatically.\n5. **No dead ends:** every error, empty and edge state has a defined screen and a recovery action.\n### 1.4 Non-goals\n- No own header, no bottom tab bar, no custom navigation chrome — Telegram owns the frame.\n- No custom fonts inside Telegram.\n- No payment processing in-app: Kaspi QR is an image + manual operator verification (unchanged).\n- No website version of the client flow. The legacy React site is retired; only the operator web\n  panel survives.\n---\n## 2. Design principles\n1. **Native-first.** Use Telegram components (`MainButton`, `BackButton`, native header, popups,\n   haptics) instead of rebuilding them. The best compliment is \"this looks like Telegram itself\".\n2. **The user's theme is law.** All colors come from `--tg-theme-*` CSS variables. Hardcoded\n   colors are allowed only as `var(..., fallback)` values for development outside Telegram.\n3. **One screen — one decision.** Each screen asks for one thing and has one primary button.\n4. **Minimize typing.** Prefill everything Telegram knows (first name, last name, `@username`);\n   use steppers, chips, and sheets instead of free-text inputs wherever possible.\n5. **States beat screens.** Loading, empty, error, offline, maintenance and expired are designed\n   states, not afterthoughts (section 9).\n6. **Rebuild trust on every screen.** Order number, amount, and current status are always visible\n   on order screens. Payments are manual — the copy says so honestly.\n7. **Flat and calm.** No gradients, no drop shadows on content, no stock photos, no decorative\n   emoji in UI (emoji live in bot messages only).\n8. **Numbers are sacred.** Amounts, dates and the order number always render with tabular numerals;\n   money is formatted `1 000 ₸` with non-breaking spaces.\n---\n## 3.
